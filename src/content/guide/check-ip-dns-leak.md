## 直接结论

打开代理软件、看到"已连接"，并不等于出口 IP 和 DNS 请求都真的经过了代理节点。是否存在泄露需要自己动手测一遍，主要检查两件事：一是访问网站时对方看到的出口 IP 是不是代理节点的 IP，二是域名解析请求有没有走本地运营商的 DNS 服务器。这两项分开检测，任何一项不对，都可能导致真实的网络位置或访问记录被暴露。

## 为什么会出现泄露

- **分流规则把域名解析排除在外**：一些客户端的分流规则只处理了流量转发，DNS 查询单独走了系统默认设置，就会出现网页能打开、但 DNS 请求仍暴露给本地运营商的情况，具体原理可以参考[DNS污染和DNS泄露](/airport/what-is-dns-leak/)。
- **代理模式覆盖不全**：系统代理模式只对遵循系统设置的应用生效，部分程序会绕开系统代理直接连接，这也是[TUN模式](/guide/tun-mode-explained/)存在的原因之一。
- **规则集写法有遗漏**：自己修改过分流规则、或者使用了不完整的规则集时，可能出现部分流量匹配不到"应该走代理"的规则，被当作"直连"处理。

## 检测步骤

### 第一步：先记录未开代理时的基准值

在关闭代理的状态下，用出口 IP 检测网站记录一次自己的真实 IP 和归属地，作为对照的基准。这一步容易被跳过，但没有基准值，后面看到的结果就没有对比意义。

### 第二步：开启代理后重新检测出口 IP

开启代理连接常用节点，再次访问同一个出口 IP 检测网站，对比两次结果：

| 检测项 | 未开代理 | 开启代理后应该出现的变化 |
| --- | --- | --- |
| 出口 IP | 你的真实公网 IP | 变为代理节点所在地区的 IP |
| IP 归属地 | 你实际所在地区 | 变为节点标注的地区 |

如果开启代理后 IP 和归属地没有变化，说明流量根本没有经过代理，需要先检查客户端是否真的处于连接状态、分流规则是否把当前测试网站错误地划入了"直连"。

### 第三步：单独检测 DNS 解析

出口 IP 正常之后，再单独测一次 DNS。原理和结果判断方式可以参考[DNS污染和DNS泄露](/airport/what-is-dns-leak/)里的说明：如果检测结果显示的 DNS 服务器归属地和你本地运营商一致，而不是代理节点所在地区，就说明存在 DNS 泄露，域名解析这一步没有真正经过代理。

### 第四步：更换节点重复测试一次

只测一次容易受偶发因素影响，比如缓存没有清空、检测网站本身响应异常。换一个不同地区的节点重复第二步和第三步，如果结果能稳定对应节点地区的变化，说明检测本身是可信的。

## 出现问题后怎么排查

- **先确认客户端连接状态**：检查是否真的显示"已连接"，而不是掉线后仍在测试。
- **检查代理模式**：系统代理模式下部分应用天然可能绕过代理，如果只有个别应用出问题，可以参考[TUN模式](/guide/tun-mode-explained/)是否更适合你的场景；如果是所有应用都有问题，大概率是规则配置的问题。
- **检查分流规则里 DNS 相关的设置**：确认客户端里"是否让 DNS 查询走代理"这类选项是开启的，具体规则写法和优先级可以参考[Clash分流规则进阶](/guide/clash-rules-guide/)。
- **清除本地 DNS 缓存后重测**：操作系统和浏览器都可能缓存旧的解析结果，修改配置后如果不清缓存，短时间内的检测结果可能还是旧数据，容易造成误判。
- **排除检测工具本身的问题**：换一个检测网站再测一次，避免单一工具的展示错误被当成真实泄露。

## 常见误判

- 把"检测网站显示的地区和节点标注的地区有细微出入"当成泄露：部分 IP 库对地区的归属判断本身存在误差，只要和真实所在地明显不同，就说明代理生效了，不需要追求和节点标注完全一致。
- 只测了一次就下结论：网络状态和缓存都会造成偶发性的结果差异，按上面的步骤换节点重复测试更可靠。
- 把"某个应用打不开"当成泄露问题：应用打不开可能是节点本身不稳定或者被限速，属于另一类问题，可以参考[机场为什么晚上会变慢](/airport/why-airport-slow-at-night/)排查，和这里说的泄露不是一回事。

## 不同设备上检测，结果可能不一样

同一个机场账号，在手机和电脑上分别测试，结果有时会不一致，常见原因有：

- **两台设备连接的不是同一个节点**：客户端通常会记住上次选择的节点，如果手机和电脑各自连了不同地区的节点，出口 IP 本来就应该不同，这不算异常。
- **系统代理模式和 TUN 模式混用**：比如电脑开了 TUN 模式、手机只用了系统代理模式，两者对"哪些流量真正经过代理"的覆盖范围不同，检测结果自然可能不一样，具体差异可以参考[TUN模式](/guide/tun-mode-explained/)的说明。
- **浏览器或系统自带的 DNS 预取功能**：部分浏览器会提前解析页面上出现的域名，如果这个预取过程没有经过代理的 DNS 设置，即使正常访问时没问题，检测网站也可能捕捉到一次走本地 DNS 的记录，这种情况建议换一个没有做预取优化的浏览器窗口重测。

如果只有一台设备测出问题，先怀疑这台设备自身的代理模式或应用设置，而不是直接认定整个机场或线路有问题。

## 检查清单

- [ ] 已记录关闭代理时的真实 IP 和归属地作为基准
- [ ] 开启代理后出口 IP 已变为节点所在地区
- [ ] 已单独完成一次 DNS 泄露检测
- [ ] 已更换至少一个不同地区节点重复测试
- [ ] 确认过客户端的分流规则里 DNS 查询走代理
- [ ] 测试前后都清理过本地 DNS 缓存，排除旧数据干扰
